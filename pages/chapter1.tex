\section{研究背景及意义}
实时渲染是聚焦于制作和分析实时图像的计算机图形学的子领域，其聚焦于在极短的时间内完成从三维几何数据到二维图像的计算与生成。在典型的实时交互应用中，系统需要持续捕获用户的输入，更新虚拟环境状态，并以较高的刷新率输出连续的图像序列。一般大于 30FPS  的渲染被称为实时渲染，10FPS 左右的我们称为可交互渲染，再慢的就是离线渲染。实时渲染技术目前广泛应用在强交互的 3D 游戏和带 3D 的应用中，例如，游戏，VR/AR，虚拟仿真等，有巨大的应用前景和商业价值。

在技术路线上，实时渲染主要分为光栅化（Rasterization）与光线追踪（Ray Tracing）两种基础架构。光栅化技术基于多边形投影原理，其算法流程高度契合 GPU 的单指令多数据流（SIMD）并行计算架构，能够以极高的效率处理大规模几何数据。然而，光栅化本质上是一种基于局部信息的计算模型，缺乏对场景全局几何拓扑的直接感知能力。因此，在处理全局光照（Global Illumination）、软阴影及物理反射时，传统光栅化管线主要依赖屏幕空间近似算法（如屏幕空间反射 SSR、屏幕空间环境光遮蔽 SSAO）或预计算技术（如阴影贴图、光照探针）。这些启发式近似方法在处理复杂遮挡关系与动态场景时，往往会产生走样（Aliasing）及物理失真问题。

相对而言，光线追踪技术通过在三维空间中模拟光线的物理传播、散射与折射路径，能够更准确地求解渲染方程，从而生成具备物理真实感的光影效果。但由于光线在场景中弹射路径具有较高的随机性，导致内存访问呈现非连续特征，难以充分利用 GPU 的并行算力，因此长期被限制在离线渲染领域。

随着 GPU 硬件算力的提升以及专用硬件光线追踪加速单元（如 RT Core）的引入，实时光线追踪技术逐渐具备了工程可行性。为平衡渲染质量与计算开销，混合渲染架构（Hybrid Rendering Architecture）成为当前的主流发展方向。该架构将光栅化在初级可见性（Primary Visibility）计算上的高效率，与光线追踪在次级光线（如反射、阴影）求解上的准确性相结合，有效弥补了单一管线的不足，是目前图形学界重点研究的核心课题。

\section{研究现状}
图形渲染管线及底层硬件经历了长期的演进过程。20 世纪 90 年代末，图形硬件主要采用固定渲染管线（Fixed-Function Pipeline），开发者仅能通过配置预设状态来控制渲染输出。2001 年起，可编程着色器（Programmable Shaders）的引入使开发者能够自定义顶点变换与像素着色逻辑。至 2006 年，统一着色器架构（Unified Shader Architecture）的提出，打破了不同着色阶段计算资源的物理隔离，为现代通用 GPU 计算奠定了基础。2018 年是实时渲染的分水岭，Microsoft 发布了 DXR（DirectX Raytracing）框架，并且NVIDIA 在同年推出了基于 Turing 架构的 RTX 平台，让实时光线追踪成为可能。

在底层图形应用程序接口（Graphics API）方面，传统 API（如 OpenGL 与 DirectX 11）由于设计于单核 CPU 时代，采用了高度封装的全局状态机模型。在这种架构下，内存管理与线程同步操作由图形驱动程序隐式处理，导致在处理复杂场景时产生较高的 CPU 驱动开销，限制了多核处理器的并发能力。为此，工业界推动了向显式图形 API（Explicit Graphics API）的范式转移，如 Vulkan 与 DirectX 12。此类 API 将显存的分配与释放、多线程命令缓冲区的录制以及管线同步屏障（Pipeline Barriers）的控制权显式移交至应用层，显著降低了驱动开销，提升了硬件算力的利用率。

渲染器是游戏引擎中核心的子系统之一，它负责图形绘制，接收渲染命令和资源数据（顶点、纹理、Shader 等），并调用 OpenGL/D3D/Vulkan 等图形 API，将游戏世界中的数据（模型、纹理、光照、摄像机等）转换为最终呈现在屏幕上的图像。由 ID SoftWare 开发的游戏《德军总部 3D（Wolfenstein 3D）》《毁灭战士（DOOM）》取得了巨大成功，其主要的开发者约翰卡马克把游戏开发可以重复使用的代码提取出来，创造了游戏引擎这一概念。DOOM 引擎是第一个用于商业授权的引擎，后来开发的 Quake 引擎是真正的 3D 引擎, 人们普遍认为游戏《雷神之锤》带来了独立 3D 显卡的革命。如今的商业游戏引擎市场基本上是 Unreal和Unity 两巨头，在开源领域也有 Orge，Godot 等引擎，当然也还有专门的渲染引擎，比如V-Ray，OctaneRender等，给许多引擎和渲染开发者提供了优秀的学习资料，促进了游戏引擎，渲染领域的发展。

在渲染引擎架构层面，随着渲染管线复杂度的增加，传统的面向对象绘制指令流逐渐难以维护。现代工业级渲染引擎广泛引入了基于数据驱动的渲染图架构RenderGraph。该架构通过构建有向无环图（DAG），在编译期自动推导各渲染通道（Render Pass）之间的数据依赖关系，从而实现显存的动态复用与同步屏障的自动插入，是目前处理复杂混合渲染管线状态调度的标准方案。

此外，在实时光线追踪的工程实践中，受限于实时计算的性能预算，系统通常仅能采用极低的采样率（如单像素单样本，1-SPP），导致原始渲染结果存在严重的蒙特卡洛噪声。因此，时空重建与降噪技术（Spatiotemporal Reconstruction and Denoising）成为当前的研究热点。以时空方差引导滤波（SVGF）为代表的算法，通过提取历史帧的时间相关性信息并结合当前帧的空间几何特征，能够有效平滑高频噪声。降噪算法的执行效率与重建质量，已成为决定混合渲染管线最终视觉表现的关键因素。

\section{本文研究内容}
本文基于 Vulkan 1.3 规范设计并实现了一个三维实时混合渲染引擎，主要研究内容包括以下几个方面。
\begin{enumerate}
    \item 研究 Vulkan 1.3 渲染管线，利用动态渲染等新特性优化引擎底层架构，探索资源管理流程。
    \item 研究已有渲染引擎架构，从而设计本引擎的架构和模块。
    \item 构建混合渲染管线，结合光栅化的高效几何处理能力与光线追踪的物理精确照明，实现高质量的软阴影与反射效果。
\end{enumerate}

\section{论文总体结构}
以下是对本论文各个章节的概要：
\begin{itemize}
    \item \textbf{第一章 绪论}：介绍实时混合渲染的研究背景、研究现状，并简述本文的主要工作。
    \item \textbf{第二章 理论基础}：深入分析 PBR 物理模型、Vulkan 渲染机制及硬件光追原理。
    \item \textbf{第三章 需求分析}：从可行性、业务流程、功能与非功能指标等方面详细阐述引擎需求。
    \item \textbf{第四章 概要设计}：论述系统分层架构、功能模块划分及显存逻辑表结构设计。
    \item \textbf{第五章 详细设计}：以需求为基础，对渲染图算法、光追逻辑及时空重建模型进行细致设计。
    \item \textbf{第六章 系统实现与测试}：系统展示核心代码实现，通过功能测试用例与性能数据验证系统有效性。
    \item \textbf{第七章 总结与展望}：总结全文工作并指出未来改进方向。
\end{itemize}

\section{本章小结}
本章阐述了混合渲染引擎的研究背景与意义，梳理了国内外图形技术的研究现状，并明确了本文的主要研究内容。最后给出了论文的整体章节安排，为后续内容的展开奠定了基础。
