\chapter{引擎架构与场景管理}

本章将详细介绍 Chimera 渲染引擎的底层基础设施构建过程，重点阐述其模块化分层架构、基于 GLTF 的场景管理方案，以及支持实时交互的摄像机系统。特别地，本章将深入推导作为实时渲染数学基石的空间变换（MVP）矩阵。

\section{引擎分层架构设计}

为了提高代码的可修改性并降低耦合度，本项目将引擎划分为核心层与平台层两个主体部分，并采用静态库（Static Library）的形式封装渲染逻辑。

\subsection{核心层 (Core Layer)}
核心层负责处理与硬件平台无关的通用逻辑：
\begin{itemize}
    \item \textbf{Layer 分层逻辑}：引入了 Overlay 和 Layer 的概念。渲染流程按层级顺序执行，而 UI 事件（如 ImGui 面板）则优先拦截输入。这种设计简化了调试界面与场景交互的冲突处理。
    \item \textbf{资源抽象}：封装了纹理（Image）、缓冲区（Buffer）及着色器（Shader）等低级对象的生命周期管理。
    \item \textbf{日志系统}：集成 spdlog，实现带颜色分级的多线程异步日志记录，辅助实时监控引擎状态。
\end{itemize}

\subsection{平台层 (Platform Layer)}
平台层直接与操作系统和图形 API 交互：
\begin{itemize}
    \item \textbf{Vulkan 环境初始化}：利用 volk 动态加载 API 入口，负责逻辑设备、交换链及验证层的配置。
    \item \textbf{输入与窗口管理}：通过 GLFW 捕获原生窗口事件，并将其转发至核心层的 Layer 系统。
\end{itemize}

\section{场景管理与资源加载}

本系统旨在处理复杂的 PBR 模型，因此在场景组织上采用了工业界的标准方案。

\subsection{基于 GLTF 的模型加载}
本项目采用 \texttt{cgltf} 库解析 GLTF 2.0 格式模型。加载流程不仅包括顶点属性（位置、法线、切线、UV）的提取，还涵盖了 PBR 材质参数（金属度、粗糙度贴图）的映射。
为了优化 GPU 传输，所有几何数据在加载后会被合并到全局顶点和索引缓冲区中。

\subsection{场景树与加速结构管理}
场景由 \texttt{Scene} 类统一管理。为了支持光线追踪，场景树在每帧更新时会执行以下操作：
\begin{enumerate}
    \item 更新每个实体的世界变换矩阵。
    \item 重新构建或更新顶层加速结构（TLAS）。每个渲染实例指向一个底层加速结构（BLAS），这种解耦允许在不重新扫描几何体的情况下实现物体的实时平移与旋转。
\end{enumerate}

\section{交互式摄像机系统与空间变换 (MVP)}

摄像机系统是用户与虚拟场景交互的桥梁，其背后的数学核心是坐标空间的连续变换。

\subsection{坐标空间变换流程}
为了将三维模型渲染到二维屏幕，顶点必须经历从局部空间到标准化设备坐标（NDC）的变换序列。

\begin{enumerate}
    \item \textbf{模型变换 (Model Matrix)}：
    将顶点从局部坐标系转换到世界坐标系。对于平移 $\vec{t}$、旋转 $R$ 和缩放 $S$，模型矩阵 $M = T \cdot R \cdot S$。
    
    \item \textbf{观察变换 (View Matrix)}：
    建立以摄像机为原点的坐标系。给定摄像机位置 $\vec{p}$、目标点 $\vec{l}$ 和上向量 $\vec{u}$，通过 Gram-Schmidt 正交化构建视图矩阵 $V$，将世界坐标转换到观察空间。
    
    \item \textbf{投影变换 (Projection Matrix)}：
    本系统采用透视投影，将视锥体内的几何体映射到裁剪空间。
    \begin{equation}
    P = \begin{bmatrix}
    \frac{1}{aspect \cdot \tan(fov/2)} & 0 & 0 & 0 \\
    0 & \frac{1}{\tan(fov/2)} & 0 & 0 \\
    0 & 0 & \frac{f}{n-f} & \frac{nf}{n-f} \\
    0 & 0 & -1 & 0
    \end{bmatrix}
    \end{equation}
\end{enumerate}

\subsection{Reversed-Z 深度缓冲技术}
在传统的透视投影中，深度值 $z$ 在近剪裁面附近变化剧烈，而在远景处精度极低，容易导致“深度冲突”（Z-fighting）。
本系统在投影矩阵推导中采用了 **Reversed-Z** 技术，将近剪裁面映射为 $z=1.0$，远剪裁面映射为 $z=0.0$，并配合浮点深度缓冲。这种方案结合 $1/z$ 的非线性特性，使得整个视锥体内的深度精度分布趋于均匀。

\subsection{弧球 (Arcball) 相机交互算法}
本系统实现了一套基于 Arcball 逻辑的编辑器相机。
\begin{itemize}
    \item \textbf{旋转}：将鼠标在屏幕上的二维偏移映射到包围球面上，计算旋转四元数，实现围绕目标点的顺滑轨道飞行。
    \item \textbf{平移与缩放}：根据相机到目标点的距离动态调整平移步长，确保在不同尺度下的操作一致性。
\end{itemize}

\section{本章小结}

本章构建了 Chimera 引擎的架构骨架。通过分层设计实现了系统解耦，通过 GLTF 场景管理支撑了复杂模型的加载与光追加速结构的更新。最后，本章推导了 MVP 空间变换矩阵，并引入 Reversed-Z 技术优化了渲染精度。这些基础设施为下一章探讨 Render Graph 调度与核心渲染管线的实现提供了必要的前提。
