\chapter{实时混合渲染相关理论}
\label{chap:theory}

本章将阐述构建实时混合渲染引擎所需的理论基石。首先从宏观视角定义渲染器及其对物理世界的简化模型；随后深入探讨图形光栅化与光线追踪的基本原理；接着论述实时混合渲染管线的“分而治之”策略；最后探讨现代图形 API 的演进及其在渲染引擎架构中的核心作用，为后续章节中引擎的具体实现奠定严密的理论基础。

\section{实时渲染相关基础理论}

\subsection{渲染模型}
渲染（Rendering）是将离散的数字描述转化为最终可见像素阵列的过程。为了在有限的算力下模拟复杂的物理世界，本项目对渲染模型进行了三层维度的抽象简化：
\begin{itemize}
    \item \textbf{相机模型}：将人眼视觉简化为针孔相机（Pinhole Camera），通过投影矩阵建立三维场景与二维成像平面的几何映射。
    \item \textbf{几何与材质模型}：利用三角形网格表征宏构拓扑，并采用基于微面元理论的材质参数（如粗糙度、金属度）描述物体表面的微观光学特性。
    \item \textbf{光源模型}：将发光体简化为点光源、方向光或具有解析分布的面积光源（Area Light），旨在平衡计算开销与光影的物理保真度。
\end{itemize}

\subsection{渲染器职责与架构设计哲学}
渲染器是图形系统的核心中枢，负责高效组织资源并驱动 GPU 指令流。现代高性能渲染器需遵循“显式声明、隐式同步”的设计原则。通过引入 \texttt{RenderGraph} 技术，系统能够将高层算法逻辑与底层资源生命周期解耦，从而在保障执行效率的同时，降低由于显式 API（如 Vulkan）手动同步带来的研发风险。

\section{图形光栅化原理}

\subsection{光栅化渲染管线流程}
光栅化（Rasterization）是现代实时图形学的核心算法，其基本思想是将连续的几何图元（通常为三角形）投影并转化为离散的像素阵列。光栅化管线通常分为以下核心阶段：
\begin{itemize}
    \item \textbf{几何阶段}：顶点着色器（Vertex Shader）执行模型、观察与投影变换，将三维坐标映射至齐次裁剪空间。随后进行裁剪与背面剔除，确保仅渲染视锥体内的可见图元。
    \item \textbf{光栅化阶段}：硬件对投影后的三角形进行扫描，确定哪些像素中心被覆盖，并利用重心坐标（Barycentric Coordinates）执行透视校正插值，为后续着色提供深度、法线及材质属性。
    \item \textbf{像素处理阶段}：片元着色器（Fragment Shader）计算最终色彩。通过深度测试解决遮挡关系，并由混合器完成最终的图像合成。
\end{itemize}

\subsection{重心坐标插值与透视校正}
在光栅化过程中，为了在三角形内部恢复顶点的属性（如 UV 坐标、法线），系统采用重心坐标插值。对于三角形内任意一点 $P$，其属性 $\phi_P$ 可表示为三个顶点属性的加权平均：
\begin{equation}
    \phi_P = \alpha \phi_A + \beta \phi_B + \gamma \phi_C
\end{equation}
由于投影变换是非线性的，直接在屏幕空间进行线性插值会导致纹理扭曲。现代 GPU 强制执行透视校正插值（Perspective Correct Interpolation），通过对属性除以深度值 $w$ 进行线性插值后再还原，确保了宏观透视关系的正确性。

\subsection{硬件加速与 Early-Z 优化}
为了进一步提升性能，现代 GPU 引入了 Early-Z 技术。在执行耗时的片元着色器之前，硬件会预先进行深度测试。如果当前像素已被遮挡，则直接跳过着色计算。这极大缓解了高复杂场景下的过度绘制（Overdraw）问题。在混合渲染中，这一特性常与 G-Buffer 预通行（Z-Prepass）结合使用，以最大化渲染效率。

\section{光线追踪原理}

\subsection{光线投射与递归追踪}
光线追踪（Ray Tracing）基于几何光学的可逆性原理。其基本流程是从相机（视点）向成像平面上的每个像素投射射线（Primary Ray），通过计算射线与场景中几何体的最近交点来确定可见性。
Whitted 风格的递归光线追踪进一步模拟了光影的物理行为：在交点处，根据材质属性递归地发射反射射线、折射射线以及向光源发射阴影射线（Shadow Ray）。这种方法能够天然地处理复杂的镜面反射、透明折射和硬阴影，弥补了光栅化在全局视觉效果上的缺失。

\subsection{光线追踪的计算挑战}
与光栅化遍历几何体的逻辑相反，光线追踪是“遍历像素”的过程。其核心开销在于高频次的“射线-几何体求交”测试。在包含百万级三角形的场景中，线性求交的复杂度不可接受，因此必须引入高效的空间加速算法。虽然光线追踪在离线渲染（如影视制作）中已应用多年，但其天然的非相干性与庞大的计算量，直到近年来硬件加速技术（RT Core）的出现才真正具备了实时执行的可能性。

\section{实时混合渲染管线}

\subsection{分而治之的渲染策略}
实时混合渲染（Hybrid Rendering）旨在结合光栅化的极高吞吐量与光线追踪的物理真实感。其核心逻辑在于根据视觉效果的频率特性与计算成本，将渲染方程解构为不同的子项：
\begin{itemize}
    \item \textbf{初级可见性}：利用光栅化快速生成 G-Buffer（包含深度、法线、反照率等），这避免了初级射线求交的庞大开销。
    \item \textbf{次级光影交互}：对于光栅化难以处理的非局部交互（如非线性软阴影、环境遮蔽及屏幕空间外的镜面反射），采用硬件加速的光线追踪进行离散采样。
\end{itemize}

\subsection{管线集成与延迟渲染架构}
混合管线通常建立在延迟渲染（Deferred Rendering）或分块/分簇渲染（Tile/Clustered Rendering）的基础之上。通过 G-Buffer 提供的空间几何上下文，光线追踪发射器（Ray Emitter）可以从像素位置出发，在世界空间内执行非相干的射线查询。最终，光栅化生成的直接照明与光线追踪生成的复杂光影项在合成阶段（Compositing）进行加权聚合，从而在保证实时性的前提下，实现接近路径追踪的效果。

\section{图形 API 与渲染引擎}

\subsection{显式图形 API 的技术特征}
现代图形 API（如 Vulkan、DirectX 12）标志着从“驱动代劳”向“开发者完全控制”的范式转变。其核心特征在于显式驱动机制：
\begin{itemize}
    \item \textbf{显式资源生命周期}：开发者直接负责显存的分配、回收及镜像状态切换（Layout Transition），消除了传统驱动程序在后台进行推测性操作产生的隐式开销。
    \item \textbf{并行指令录制}：支持多线程并行录制命令缓冲（Command Buffer），彻底解决了传统 API 在 CPU 侧的单线程驱动瓶颈，极大提升了指令吞吐量。
    \item \textbf{精细化同步控制}：利用 Fence、Semaphore 和 Barrier 显式控制 GPU 内部任务的执行顺序与读写依赖（RAW/WAR），确保了光栅化与光追任务切换时的显存一致性。
\end{itemize}

\subsection{渲染引擎的抽象层职责}
为了平衡开发效率与硬件性能，现代渲染引擎不仅是 API 的封装器，更是复杂系统的调度中枢。其核心职责包括：
\begin{itemize}
    \item \textbf{Bindless 资源管理}：通过描述符索引（Descriptor Indexing）技术，将海量场景资源（纹理、材质缓冲区）一次性绑定至全局资源池。着色器通过索引实现 $O(1)$ 复杂度的随机访问，彻底消除了传统渲染中频繁切换状态产生的 CPU 开销。
    \item \textbf{自动化任务调度 (\texttt{RenderGraph})}：渲染引擎通过构建有向无环图（DAG）来描述渲染任务。\texttt{RenderGraph} 能够自动推导资源的生命周期、自动插入同步屏障并管理物理资源的复用，使开发者能专注于混合渲染算法的逻辑实现。
    \item \textbf{跨硬件特性适配}：引擎通过特征检测机制，根据硬件能力动态启用光线追踪扩展（如 \texttt{VK\_KHR\_ray\_tracing\_pipeline}）或动态渲染（Dynamic Rendering），确保管线在不同代际 GPU 上的兼容性与稳定性。
\end{itemize}
