\chapter{实时混合渲染相关技术}
\label{chap:related_tech}

本章将对构建实时混合渲染器所涉及的核心技术进行系统性介绍。首先探讨光栅化与光线追踪两种基础渲染技术的原理及优劣；随后详细阐述渲染管线中的坐标系统与空间变换逻辑；接着论述作为现代材质表现基石的基于物理的渲染（PBR）理论；并分析现代 GPU 硬件架构与着色器技术。最后，本章将介绍混合渲染管线的整体架构及其图形 API 的选型依据，为后续章节的设计与实现奠定理论基础。

\section{实时混合渲染技术}
渲染是将三维场景信息转换为二维图像的技术过程，本质上是对物理世界光影传播规律的数学模拟。渲染的数据源通常包含几何模型、相机参数和光源信息。根据处理这些数据的方式不同，主要分为以下两种主流算法：

\subsection{光栅化}
光栅化（Rasterization）是目前实时渲染领域的核心算法。其基本思想是将连续的三角形图元离散采样为屏幕上的像素片元。该过程通过坐标变换、视口裁剪与投影映射，将矢量几何资源转化为二维像素阵列，并结合深度测试（Z-Buffer）解决遮挡关系。光栅化算法具备极高的并行度，能够充分利用 GPU 的固定管线硬件加速，实现极高的渲染帧率，但难以处理复杂的全局光影交互。

\subsection{光线追踪}
光线追踪（Ray Tracing）遵循几何光学的可逆性原理。它从相机视角向场景发射射线，计算射线与几何体的最近交点，并递归地追踪反射、折射与阴影射线，模拟真实世界的光照传递。相较于光栅化，光线追踪能天然实现物理精确的镜面反射、软阴影和透明效果。然而，由于高频次的射线-几何体求交运算开销极大，直到硬件加速单元（RT Core）的出现，实时光线追踪才成为可能。

\section{坐标系统与空间变换}
在实时渲染中，将三维模型最终显示在二维屏幕上需要经过一系列严格的空间变换，这些变换通常通过 4x4 矩阵运算实现，即 MVP 变换。

\subsection{坐标空间层次}
渲染管线涉及以下五个核心空间层次：
\begin{itemize}
    \item \textbf{模型空间（Local Space）}：物体自身的局部坐标系，用于定义其几何拓扑。
    \item \textbf{世界空间（World Space）}：所有物体在场景中的统一参考系。通过模型矩阵（Model Matrix）实现从局部到世界的转换，该矩阵由平移、旋转和缩放（TRS）分量组合而成。
    \item \textbf{观察空间（View Space）}：以相机为原点、视线方向为轴的坐标系。通过观察矩阵（View Matrix）将物体定位在相机视野内。
    \item \textbf{裁剪空间（Clip Space）}：应用投影矩阵（Projection Matrix）后的空间。该空间用于执行视锥体裁剪，并为后续透视除法做准备。
    \item \textbf{屏幕空间（Screen Space）}：最终映射到显示器像素阵列的二维空间。
\end{itemize}

\subsection{MVP 变换矩阵}
顶点着色器（Vertex Shader）的核心职责是将顶点从模型空间变换至裁剪空间。其数学表达为：
\begin{equation}
    \mathbf{v}_{clip} = \mathbf{P} \cdot \mathbf{V} \cdot \mathbf{M} \cdot \mathbf{v}_{local}
\end{equation}
其中，$\mathbf{M}$、$\mathbf{V}$、$\mathbf{P}$ 分别代表模型、观察与投影矩阵。在混合渲染中，光栅化阶段依赖完整的 MVP 变换生成 G-Buffer；而在光线追踪阶段，射线通常在世界空间发射，因此仅需模型矩阵来构建加速结构。

\subsection{逆变换与时域重投影}
逆矩阵在高级渲染算法中具有重要作用。例如，利用当前帧 MVP 矩阵的逆矩阵 $\mathbf{(PV)}^{-1}$，可以将屏幕像素还原回世界空间位置。结合上一帧的矩阵信息，可以实现时域重投影（Reprojection），这是 SVGF 降噪算法和 TAA 抗锯齿技术实现帧间数据复用的理论前提。

\section{基于物理的渲染}
基于物理的渲染（Physically Based Rendering，简称 PBR）是一套遵循能量守恒定律的材质与光照理论体系。其核心目标是确保物体在不同光照环境下的视觉表现始终符合物理规律。

PBR 的核心组成部分包括：
\begin{itemize}
    \item \textbf{基于物理的光照模型}：利用双向反射分布函数（BRDF）模拟光线与物体表面的相互作用，遵循菲涅尔效应（Fresnel Effect）。
    \item \textbf{基于物理的材质模型}：通过金属度（Metallic）、粗糙度（Roughness）和基础颜色（Albedo）等具有明确物理含义的参数来精准描述物体表面属性。
\end{itemize}
PBR 的引入极大简化了材质制作流程，并为混合渲染器提供了统一的色彩表现基础。

\section{现代 GPU 架构与着色器技术}
理解底层硬件的执行机制是构建高性能 Vulkan 渲染器的关键。

\subsection{GPU 并行计算架构}
与核心数较少、注重逻辑分支预测的 CPU 不同，GPU 拥有数千个计算核心。它采用单指令多线程（SIMT）架构，极度擅长处理相互独立的并行任务（如逐顶点变换和逐像素着色）。现代 GPU 还引入了硬件加速单元（如 RT Core）专门负责射线-边界体积层次结构（BVH）的遍历与求交，这是混合渲染器能够实时运行的硬件基石。

\subsection{可编程着色器}
开发者通过着色器（Shader）直接操控 GPU 资源。在本项目中，涉及以下关键着色器阶段：
\begin{itemize}
    \item \textbf{顶点着色器}：负责几何变换与 MVP 运算。
    \item \textbf{片元着色器}：负责光栅化后的像素着色，实现 PBR 光照计算。
    \item \textbf{光线追踪着色器}：包含 Raygen（光线生成）、Closest Hit（最近交点）等，用于非相干的光学采样。
    \item \textbf{计算着色器（Compute Shader）}：用于通用的高性能计算，如 SVGF 算法中的时域滤波与降噪。
\end{itemize}

\section{混合渲染管线架构}
混合渲染管线融合了两种技术的优势，遵循“光栅化为主、光线追踪为辅”的设计哲学。

其典型执行流程包括：
\begin{enumerate}
    \item \textbf{几何预处理与光栅化}：快速生成 G-Buffer，提取场景的深度、法线和材质信息。
    \item \textbf{光线追踪辅助计算}：针对非局部光影交互（如软阴影、环境遮蔽），利用硬件加速进行局部光线采样。
    \item \textbf{后期融合与降噪}：将噪声较强的光追采样结果与光栅化底图融合，并通过降噪算法实现平滑的高质量画面。
\end{enumerate}

\section{图形 API 选型分析}
图形 API 是连接软件逻辑与硬件能力的桥梁。

\subsection{主流 API 特征对比}
目前业界主流 API 包括 OpenGL、DirectX 与 Vulkan。OpenGL 虽然跨平台性好，但驱动负担重，多线程能力差；DirectX 12 提供了完善的光线追踪支持，但局限于微软生态。

\subsection{选择 Vulkan 的依据}
Vulkan 作为新一代跨平台显式 API，具有以下核心优势：
\begin{itemize}
    \item \textbf{显式硬件控制}：允许开发者直接管理内存分配与线程同步，极大减少了 CPU 开销。
    \item \textbf{高效的多线程指令录制}：完美契合现代多核 CPU，提升了复杂场景下的吞吐量。
    \item \textbf{完善的光线追踪扩展}：通过 \texttt{VK\_KHR\_ray\_tracing} 系列扩展，提供了对现代 GPU 光追硬件的底层访问能力。
\end{itemize}

\section{本章小结}
本章系统论述了构建实时混合渲染器的理论基础。从渲染技术的演进出发，详细分析了坐标变换数学模型、PBR 材质体系及 GPU 并行架构。通过对混合管线与图形 API 的深入剖析，确立了以 Vulkan 为核心的技术路线。这些理论支撑将为后续章节中引擎架构的设计与各渲染组件的实现提供坚实指引。
