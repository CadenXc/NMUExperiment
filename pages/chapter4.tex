\chapter{概要设计}
\label{chap:general_design}

本章将对渲染引擎进行宏观架构设计。首先从渲染器在图形系统中的角色出发，确立系统的设计目标，随后详细阐述本项目采用的五层分层拓扑架构、核心模块划分以及 GPU 侧的资源组织方案。

\section{渲染器设计概述}
渲染器是游戏引擎中最核心的子系统之一，它负责图形绘制，接收渲染命令和资源数据（顶点、纹理、Shader 等），并调用 OpenGL/D3D/Vulkan 等图形API，将游戏世界中的数据（模型、纹理、光照、摄像机等）转换为最终呈现在屏幕上的图像。
渲染引擎的设计目标是构建一个具备现代工业级特性的混合渲染平台。在底层架构上，它追求与现代商业引擎相似的高内聚、低耦合特性，具备模型异步加载、资源自动管理及事件高效响应等基础能力，为上层复杂的混合渲染算法提供稳定的调度底座。

\section{系统整体架构设计}

\subsection{架构总体思路}
在系统实现层面，本项目参考了开源渲染引擎模板 \texttt{Walnut} 的分层设计哲学。 \texttt{Walnut} 以其简洁的“应用—逻辑层”（Application-Layer）堆栈架构著称，极大地降低了 Vulkan 环境下 UI 交互与渲染任务耦合的复杂度。本项目继承了其微内核设计中的 RAII 资源管理逻辑、单例中枢访问模式以及基于钩子函数（如 \texttt{OnUpdate}、\texttt{OnImGuiRender}）的事件分发机制。

然而，为了满足实时混合渲染对复杂计算管线调度的严苛需求，本项目在 \texttt{Walnut} 的基础上进行了深度架构升华。主要体现在：
\begin{itemize}
    \item \textbf{宏观分层标准化}：参考 \texttt{GAMES104} 的工业级引擎标准，将原本扁平的逻辑层级重构为严格的“工具、功能、资源、核心、平台”五层拓扑架构（详见 4.2.2 节）。
    \item \textbf{调度逻辑数据驱动}：针对光栅化与光线追踪的频繁切换与同步痛点，本项目引入了 \texttt{RenderGraph} 调度引擎，取代了基础框架中的线性指令录制模式，实现了基于有向无环图（DAG）的资源生存区间分析与自动化管线同步。
\end{itemize}
通过这种“底层借鉴、核心创新”的设计思路，本引擎既保留了开发的高效性，又具备了支撑现代混合渲染算法的灵活性。

\subsection{五层分层拓扑架构}
本项目参考现代游戏引擎架构，采用了五层分层拓扑架构。整个引擎从顶层应用到底层硬件划分为五个逻辑层，通过严格的单向依赖关系确保系统的高度解耦，如图 \ref{fig:renderer_architecture} 所示。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{chapter3/renderer_architecture.png}
    \caption{引擎五层分层拓扑架构图}
    \label{fig:renderer_architecture}
\end{figure}

\begin{enumerate}
    \item \textbf{平台层 (Platform Layer)}：引擎的硬件抽象层（HAL）。其核心职责是定义系统与底层图形 API 及操作系统之间的通信边界，确保上层逻辑与具体硬件实现的物理隔离。
    \item \textbf{核心层 (Core Layer)}：提供全局基础设施服务。该层专注于为全引擎提供底层的任务并行调度、显存/内存原始分配策略以及基础数学运算支持，是整个系统运行的基石。
    \item \textbf{资源层 (Resource Layer)}：负责资产的生命周期管理与数据组织。其职责是建立一套标准的数据加载与存储规范，将磁盘上的原始资源（模型、贴图等）转化为引擎可高效访问的内存对象。
    \item \textbf{功能层 (Function Layer)}：引擎的渲染算法驱动核心。该层负责协调资源层的数据与核心层的计算能力，实现具体的混合渲染管线调度、可见性判定以及复杂的信号重建算法。
    \item \textbf{工具层 (Tool Layer)}：位于架构顶端，直接面向开发者。其通过调用功能层提供的接口，实现可视化的交互调试、性能实时监控以及渲染参数调优等功能。
\end{enumerate}

\section{核心功能模块划分}
基于前述的五层分层拓扑架构，本渲染引擎在逻辑上被垂直切分为五个核心功能模块。这些模块通过预定义的接口进行协同，旨在确保底层硬件效能充分释放的同时，实现上层渲染算法与底层系统服务的高度解耦。本节将详细阐述各模块的设计动机、职责范围及其在系统中的核心作用。

\subsection{平台适配模块}
平台适配模块是整个渲染引擎的硬件底座。由于 Vulkan API 具有极高的操作精细度与极其繁琐的样板代码，直接在业务逻辑层调用底层 API 会导致代码耦合度过高且难以维护。本模块的设计动机在于构建一套轻量级的硬件抽象层（HAL），通过封装 \texttt{VulkanContext} 单例来统一管理物理设备筛选、逻辑设备创建及交换链（Swapchain）的重建逻辑。

此外，为了提升程序在不同供应商显卡驱动下的兼容性，模块引入了 \texttt{volk} 动态加载机制。该模块的核心职责是屏蔽底层硬件接口的复杂性与平台差异，为上层模块提供一个稳定、透明且符合工业标准的图形运行环境。

\subsection{核心框架模块}
核心框架模块作为引擎的“中枢神经”，负责协调各子系统的生命周期与底层系统服务。在现代渲染引擎中，应用状态的有序切换、窗口事件的实时响应以及跨线程的任务调度是决定系统稳定性与流畅度的关键。本模块通过 \texttt{Application} 单例类驱动全局主循环，并利用 \texttt{LayerStack} 机制实现调试 UI 与核心渲染逻辑的物理分离。

针对实时渲染对 CPU 多核并行的迫切需求，模块内规划了常驻线程池系统（TaskSystem），旨在通过非阻塞的异步调用提升系统整体的任务吞吐量。同时，集成 \texttt{VMA} 显存分配器实现显存的池化管理，通过减少与操作系统的直接交互来规避显存碎片化与申请开销，为大规模混合渲染提供坚实的底层支撑。

\subsection{资源管理模块}
资源管理模块负责引擎资产（Assets）与场景数据（Scene Data）的组织与生命周期管控。混合渲染场景通常包含数百万个面片与大量的 4K 贴图，若缺乏统一的资源调度，会导致重复加载与显存溢出。本模块的设计目标是建立一套全异步的资产导入流水线，利用多线程技术实现模型解析与贴图解码的并行化。

在场景组织方面，模块采用了基于组合优于继承思想的实体—组件（ECS）架构，将几何数据与变换逻辑解耦。其关键职责在于同步维护光线追踪所需的底层（BLAS）与顶层（TLAS）硬件加速结构，确保场景实体的任何变动都能高效地反馈至 GPU 的空间索引中，从而支撑实时的光影查询。

\subsection{渲染引擎模块}
渲染引擎模块是系统的逻辑中枢与算法核心，其主要任务是将场景描述转化为最终的像素产出。在 Vulkan 的显式同步架构下，手动维护复杂的同步屏障与资源布局转换极易引发“同步地狱”。本模块引入了数据驱动的 \texttt{RenderGraph} 调度引擎，通过分析任务间的读写依赖自动规划执行时序，实现了渲染逻辑与底层同步细节的深度解耦。

本模块拟驱动一套完整的混合渲染管线（Hybrid Render Path）：首先利用光栅化管线采集高精度的 G-Buffer 几何分量；随后基于硬件加速的光线追踪技术生成阴影、AO 与间接光原始信号；最后通过复杂的 SVGF 降噪算法与 TAA 抗锯齿技术进行信号重建。该模块的设计体现了引擎从“确定性提取”到“随机性生成”的渲染演进。

\subsection{交互调试模块}
交互调试模块旨在为开发者提供一个直观的“引擎之窗”。混合渲染管线的调试极其复杂，中间附件（如法线贴图、方差图）的正确性直接决定了最终画质。本模块基于 \texttt{Dear ImGui} 构建了嵌入式的编辑器层（EditorLayer），提供了实时的资源浏览器与场景层级视图。

其核心价值在于实现“参数动态绑定”与“实时性能诊断”。通过图形化界面，开发者可以动态调节降噪步长、曝光系数等关键参数，并实时观察 GPU 各阶段的纳秒级耗时。这种即时反馈机制显著缩短了算法调优的迭代周期，是系统工程化程度的重要体现。


\section{渲染数据流图 (DFD)}
系统的渲染流程体现了从“CPU 资产描述”到“GPU 像素呈现”的高度自动化转换。其顶层数据流转逻辑体现了资产、逻辑与硬件指令的协同，如图 \ref{fig:render_dfd} 所示。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.4\textwidth]{figures/chapter4/render\_dfd\_refined.png}
    \caption{系统渲染数据流图 (DFD)}
    \label{fig:render_dfd}
\end{figure}

整个流转过程可分为三个核心阶段：
\begin{enumerate}
    \item \textbf{资产预处理流 (CPU / TaskSystem)}：由多线程任务系统驱动，并行执行 GLTF 模型解析与贴图解码。随后在 GPU 侧分配物理显存并上传数据，同步完成底层（BLAS）与顶层（TLAS）加速结构的构建，为光追逻辑准备空间上下文。
    \item \textbf{逻辑调度流 (RenderGraph Engine)}：调度中枢接收渲染路径的声明式配置，注册虚拟 Pass 节点及其资源依赖。通过拓扑排序确立执行序列，并基于资源生存区间分析实现自动化管线同步与同步屏障（Barriers）的自动化插入。
    \item \textbf{硬件指令流 (GPU Pipeline)}：引擎将逻辑节点转化为实际的 Vulkan 指令流。GPU 依次执行光栅化 G-Buffer 采集、硬件加速射线查询以及基于 SVGF/TAA 的画质重建算法，最终将混合渲染结果提交至交换链进行呈现。
\end{enumerate}

\section{本章小结}
本章完成了引擎的宏观架构设计。通过五层分层拓扑架构确立了系统的解耦原则，并详细定义了六大核心功能模块的逻辑职责。显存逻辑与渲染数据流图的定义为后续详细设计中的具体算法实现提供了坚实的基础。
